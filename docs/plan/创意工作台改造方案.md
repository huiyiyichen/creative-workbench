# 创意工作台改造方案

现状与问题：`现状与问题清单.md`（每条问题对应本方案的章节）。

工作台细则：`创作工作台设计与实现.md`。

样张：`docs/design/direction-a-grading.html`（方向 A 调色台，浏览器直接打开；`#graph` 进入灵感库图谱）。样张侧栏是早期版本，导航以 11.1 为准。

## 0. 定位

帮你采集热点、思路、灵感和素材，长期追踪话题，在工作台里完成简单创作，再发布或制作成图片和视频。

```text
采集（榜单 / 账号订阅 / 追踪词）→ 分析漏斗（先免费初筛，再按预算分析）
  → 发现：今日 / 热点 / 报告 / 专题
  → 灵感库：收藏、提示词、仓库、美术素材、生成图、随笔、风格与模板；与 Obsidian 双向同步
  → 创作项目：选题与创意 → 文稿 → 定稿（可用灵感生图）
  → 产出：小红书 / 知乎 / 公众号版本、一键成片、视频提示词包、MV
  → 外部：飞书通知、飞书多维表格（后续）
```

贯穿全程：多 agent 按流程协作完成研究、写作、审校、制作；每一步都能可视化查看、追溯来源。

## 1. 已确认的决定

| 事项 | 决定 |
|---|---|
| 二开策略 | 沿用后端的采集、分析、评分、聚类、报告和成片流水线；前端和创作流程重写；多用户残留逐步清理（2.1） |
| 设计方向 | 方向 A「调色台」；只做暗色，文稿编辑区为浅色纸面；只做桌面端 |
| 底层架构 | 确定性数据底座 + 工作台工具（MCP）+ 多 agent 编排层 |
| 多 agent | 工作台内部按角色分工、按流程模板协作，设人工关卡；外部 agent 是可替换的执行者（2.2） |
| 编排框架 | LangGraph 负责流程；模型调用、产物溯源和界面自己做（2.2） |
| 外部 agent | DeepSeek Harness、Claude Code、Codex（2.2） |
| 可追溯 | Agent 运行、产物来源、内容经历、人工决定都能追溯，并以节点图、时间线、调用树、溯源图展示（2.3） |
| 灵感库 | 一个库。素材只能参考；风格和模板写成了规则，可以在项目里直接套用。收藏时不选类别（6） |
| Obsidian | 双向同步，是演示重点；工作台内置图谱（6.8） |
| 定稿 | 定稿锁定文案层；视觉风格、表现方案、制作方式、画幅、字幕卡属于制作层，修改不撤销定稿；内容形态属于文案层 |
| 选题结论 | 系统直接给「值得做 / 观察 / 跳过」和一句理由；你可以标「不对」（4.3） |
| 分析成本 | 免费初筛 → 同一事件只分析一次 → 两段式分析 → 每日预算；点开、收藏、用进项目时按需补分析（4.1、4.2） |
| 自动处理 | 能撤销、起保护作用的动作自动执行；改变长期内容或花钱的动作点一下才执行；全部记录、可撤销（3.9） |
| 采集空档 | 后台服务开机自启，关闭界面不停采集；关机空档在开机后补采，按发布日期归档；空档只生成一份回看（3.7、5.4） |
| 母题 | 只作为追踪词的预设，不保留主推 / 储备 / 观察 / 低相关分层 |
| 平台顺序 | B站、YouTube、GitHub、HN / Reddit 先行；抖音、小红书在阶段 4；X 暂不接 |
| 小红书 / 抖音 | 本机浏览器 + 登录态；用单独的采集账号；低频；遇到验证码暂停并提示手动处理 |
| 生成服务 | 生图、视频生成按通用接口接入，设置里填地址、Key、模型；AI 音乐预留接口（8） |
| MV 歌曲 | 你提供音频和 LRC |
| 发布 | 平台适配 + 复制 / 导出；公众号草稿箱为后续可选项 |
| 字幕 | 平台字幕自动拉取；语音转写在收藏或用于创作时按需触发（千问） |
| 封面 | 视频与图文显示真实封面，采集时缓存到本地；无封面时用生成封面 |
| 评论 | 作为条目的附属信息，只在条目详情里查看；收藏、用作项目来源或手动加载时采集（3.5） |
| 趋势时间口径 | 按发布时间计算，缺发布时间时用采集时间 |
| 通知 | 应用内 + Windows 系统通知；飞书可选（10.1） |
| 飞书多维表格 | 后续接入：选题写入飞书表格（10.2） |
| 模板默认 | 参考片段可关联采集内容；内置模板复制后编辑；视觉风格也标注适用形态 |

## 2. 架构

```text
界面：今日 / 热点 / 报告 / 专题 / 灵感库 / 项目 / 作品 / 任务 / 信源 / 设置
────────────────────────────────────────────────────────────
Agent 层：流程引擎（LangGraph）+ 角色（研究员、策划、写手、审校、分镜、美术、制作、质检、平台编辑）
        + 外部执行者（DeepSeek Harness、Claude Code、Codex）
        ↕ 只通过工作台工具读写；全部过程写入运行记录
工作台工具（MCP 服务）：搜索灵感库、读取原文 / 字幕 / 评论、加入收藏、记随笔、
        创建项目、提交文稿修改建议、触发追踪词搜索、生图、渲染视频
────────────────────────────────────────────────────────────
数据底座：采集调度与同步记录、分析漏斗、内容与指标、封面与评论、灵感库与素材、
        专题与报告、版本 / 定稿、生成记录、渲染与配音、运行记录与溯源
```

- **Agent 适配层**：统一接口 `run(task, workspace, tools, budget) → 事件流`。实现：内部模型调用、DeepSeek Harness（现有）、Claude Code（Claude Agent SDK）、Codex（`codex exec --json`）；详见 2.2。
- **任务权限**：各角色的工具范围见 2.2；写作类角色只提交修改建议，由你确认后生效；制作只写自己的作品目录。
- **预算**：分析、生成、agent 任务各有每日上限；任务中心和采集页显示花费，可随时停止。
- **代码分层**：沿用 `api → services → repositories → models`；agent 的写入走工作台 API 校验。

### 2.2 多 agent 编排

多 agent 指工作台内部多个分工明确的角色按流程协作；外部 agent 是其中可替换的执行者。角色之间不直接对话，只通过产物交接（2.3）。

**角色**

| 角色 | 做什么 | 可用工具 | 产出 |
|---|---|---|---|
| 主管 | 处理开放式任务：拆分、派活、汇总；固定流程不经过它 | 读取全部产物、启动其他角色 | 任务计划 |
| 研究员 | 搜灵感库和网页，读原文、字幕、评论 | 搜索灵感库、网页搜索与抓取、读取原文 / 字幕 / 评论 | 研究简报（每条结论带出处） |
| 策划 | 根据研究和选题结论想角度 | 读取研究简报、结论、情绪板 | 方向卡 |
| 写手 | 按模板写稿，按意见修改 | 读取产物与模板；提交文稿或修改建议 | 文稿版本、修改建议 |
| 审校 | 逐句对照出处核查事实；检查平台规则、字数、语气 | 读取文稿与来源 | 意见清单（只提意见，不改稿） |
| 分镜 | 把定稿脚本拆成分镜 | 读取定稿；提交分镜建议 | 分镜表 |
| 美术 | 写生图提示词，生成关键帧和封面 | 搜索灵感库素材、生成服务（8） | 生成图 |
| 制作 | 生成 Remotion 工程并渲染 | 作品目录读写、固定渲染器 | 成片、工程 |
| 质检 | 检查时长、字幕对齐、黑帧、静音；抽帧与分镜比对 | 读取成片与分镜、视觉模型 | 质检报告 |
| 平台编辑 | 改写小红书 / 知乎 / 公众号版本 | 读取定稿与平台规则 | 平台稿 |

**执行者**：每个角色由内部模型调用或外部 agent 执行，在流程设置里可换。
- 内部：现有模型层 + 结构化输出，用于研究、策划、写作、审校、分镜、平台改写、质检。
- 外部：DeepSeek Harness、Claude Code、Codex，用于需要读写文件、运行命令的任务（制作、复杂研究）。

**协作方式**
- 接力：上一个角色的产物交给下一个。
- 并行：例如 3 个写手各写一个角度，供你挑选。
- 评审循环：写手与审校来回修改，最多 2 轮。
- 人工关卡：选方向、接受修改、定稿。前两个可在流程设置里关闭；定稿始终由你确认。流程停在关卡时通知你。

**内置流程**

| 流程 | 步骤 |
|---|---|
| 选题研究 | 研究员并行（按平台分工）→ 汇总 → 策划出方向 →〔选方向〕 |
| 成稿 | 写手 → 审校 → 写手修改（最多循环 2 轮）→〔接受修改〕→〔定稿〕 |
| 讲解视频 | 分镜 → 美术出关键帧 → 制作 → 质检；不通过退回制作，最多 2 次 |
| 音乐 MV | 分镜（按 LRC 对齐）→ 美术 → 制作 → 质检 |
| 平台改写 | 平台编辑并行 → 规则校验 |
| 全流程 | 选题研究 → 成稿 → 讲解视频 + 平台改写，保留人工关卡 |

**流程模板**
- 用 YAML 描述：节点、角色、执行者、模型、并行数、循环上限、关卡开关、预算。加载时编译为 LangGraph 图。
- 设置里可调参数；模板本身是声明式配置，以后可以加拖拽编辑。

**编排引擎：LangGraph**
- LangGraph 负责：节点图与并行分支、状态持久化（PostgreSQL checkpointer，用同一个库）、中断与恢复（人工关卡）、从任意步骤回放和分叉重跑、事件流、单步重试。
- 自己做：
  - 模型调用：沿用现有模型层（路由、加密密钥、用量计费、预算），不用 LangChain 的模型封装。
  - 产物与溯源：业务数据存自己的表（2.3）；LangGraph 的状态快照只用于恢复和重跑。
  - 界面：节点图自己画，图结构从 LangGraph 导出，运行状态通过 SSE 推送。不使用 LangSmith；调试时可接本地 Langfuse。
- 长任务：外部 agent 和渲染在任务中心运行；流程在该节点中断，任务结束后带结果恢复。
- 依赖：`langgraph`、`langgraph-checkpoint-postgres`，锁定版本。

**外部 agent 接入**

| agent | 启动方式 | 过程记录来源 | 工作台数据 | 限制 |
|---|---|---|---|---|
| DeepSeek Harness | 沿用现有方式，在作品目录运行 | 解析运行日志 | 制作契约文件 | 只写自己的作品目录 |
| Claude Code | Claude Agent SDK（Python） | SDK 消息流与工具调用钩子 | MCP 工作台工具 | 限定工作目录和可用工具 |
| Codex | `codex exec --json` | 逐行 JSON 事件 | MCP 工作台工具 | 沙箱只允许写工作目录 |

- 每次运行一个独立工作目录；运行前后对比目录，改动的文件登记为该步骤的产物。
- 只传入所需的密钥，不继承完整环境变量。
- 每次运行发放一个限定范围的令牌（可用工具、可访问的项目、过期时间），MCP 服务按令牌校验，并记录每次调用。
- 各自的事件统一转换为追溯格式（消息、工具调用、文件改动、花费），节点图里与内部角色显示方式一致。

**预算与停止**
- 每次运行设上限：花费、时间、步数、循环次数；超限时暂停，由你决定追加预算或停止。
- 运行可随时停止；每个角色可单独选模型。

**入口**：项目里的「AI 给出方向」「AI 写初稿」「AI 修改」「开始制作」「生成平台版本」分别启动对应流程；项目页有「一键全流程」；任务中心列出所有运行。

### 2.3 可视化与追溯

**追溯对象**
1. Agent 运行：每次流程运行的每个步骤、每次模型调用和工具调用。
2. 产物：每份产物的版本和来源关系。
3. 内容经历：每条内容从采集到成片的过程。
4. 人工决定：关卡上的选择、接受或拒绝的建议、定稿。

**数据**

| 表 | 内容 |
|---|---|
| `agent_runs` | 流程模板与版本、项目、触发方式、状态、预算与花费、开始 / 结束时间、LangGraph thread id、父运行（分叉重跑时） |
| `agent_steps` | 运行、节点、角色、执行者（内部 / DeepSeek Harness / Claude Code / Codex）、状态、尝试次数、输入产物、输出产物、模型、token、花费、耗时、错误 |
| `trace_spans` | 调用树：步骤下的每次模型调用、工具调用、外部 agent 事件；父子关系、起止时间、属性（按 OpenTelemetry GenAI 约定命名）、载荷引用 |
| `artifacts` | 产物：类型（研究简报 / 方向卡 / 文稿版本 / 意见清单 / 分镜表 / 提示词 / 生成图 / 成片 / 平台稿 / 质检报告）、版本、内容引用、产出步骤 |
| `artifact_links` | 产物之间、产物与采集内容 / 灵感库条目之间的关系：派生自、引用、审校、替换；可细到段落或分镜 |
| `decisions` | 人工决定：所在关卡或对象、选项、你的选择、时间 |
| `content_journey` | 内容经历：内容、环节（采集 / 预筛 / 初筛 / 归并 / 快速判断 / 完整分析 / 结论 / 收藏 / 用于项目 / 进入成片）、结果摘要、关联的同步记录 / 模型调用 / 运行、时间 |

- 现有 `llm_call_logs` 只记 token 和花费；增加 `run_id`、`step_id`、`content_id` 和提示词 / 回复的载荷引用。所有模型调用（含分析漏斗）都写这张表。
- 载荷（完整提示词、回复、工具参数与结果）压缩后存 `data/traces/`，数据库只存引用和摘要。写入前脱敏：API Key、Cookie、Authorization。
- 现有项目版本（`studio_revisions`）登记为文稿版本产物，不重复存内容。
- 运行记录不自动清理；设置里显示占用空间，可手动清理旧运行的载荷（保留结构和摘要）。

**界面**

| 视图 | 内容 |
|---|---|
| 节点图 | 达芬奇调色页节点图样式：节点是步骤（角色图标、执行者、状态色），连线是产物流向；并行分支横向展开，评审循环显示轮次；运行中实时更新。点节点打开详情：输入产物、渲染后的完整提示词、模型与参数、工具调用（参数和结果，长内容折叠）、输出、token、花费、耗时、尝试次数、错误与处理建议 |
| 时间线 | 每个步骤一条横条，显示并行、等待人工的时长、重试 |
| 调用树 | 运行 → 步骤 → 模型调用 / 工具调用 / 外部 agent 事件，逐层展开，每层显示耗时和花费；可按类型、错误筛选 |
| 溯源图 | 任何产物点「溯源」：向上展开来源链，直到采集内容和灵感库条目；向下显示被谁使用。文稿段落和分镜可以单独溯源，例如：成片 → 分镜 v3 第 5 镜 → 文稿 v8 第 4 段 → 研究简报第 2 条 → 采集内容 #123（原文链接、发布时间） |
| 内容经历 | 条目详情里的时间线：哪个信源、哪次同步采到 → 预筛 → 初筛分与各项信号 → 归入的事件 → 快速判断 / 完整分析（可看提示词和回复）→ 结论怎么得出 → 收藏 → 用于哪个项目 → 进入哪个成片 |
| 引用 | 写手产出的每个事实带引用锚点，点开显示原文摘录；审校把没有出处的句子标黄 |

**重跑与对比**
- 节点详情里点「从这里重跑」：可改提示词、换模型或执行者；生成一个分叉运行，原运行保留，节点图上并排显示分支。
- 「对比」：两次运行同一节点的输出并排比较（文稿按段落、分镜按镜、图片并排）。
- 采用分叉结果后，可以让后续步骤自动接着跑。

**位置**
- 任务中心：每次运行可打开节点图、时间线、调用树。
- 项目：「过程」页签，列出本项目所有运行和人工决定。
- 所有产物：「溯源」按钮。
- 条目详情：「经历」。
- 导出：运行记录导出 JSON / Markdown；运行摘要（流程、步骤、花费、关键决定、溯源链）写入 Obsidian 项目笔记。

## 3. 采集

### 3.1 信源

- 只有一个「信源」页，按平台分组；取消系统 / 我的之分。
- 添加方式：粘贴链接或输入关键词，自动识别类型；识别结果可手动改。
- 三类信源：

| 类型 | 用途 | 示例 |
|---|---|---|
| 订阅 | 跟踪账号 | B站 UP 主、抖音账号、小红书账号、YouTube 频道、GitHub 仓库发布 |

| 榜单 | 平台热榜 | 现有 21 个热榜，加 B站热门 / 分区排行、GitHub Trending、YouTube 趋势 |

- 追踪词同时用于：初筛加分（4.1）、升温曲线（5.2）、自动成为专题（5.5）。
- 母题只作为追踪词的预设：系统母题模板改为内置的追踪词预设。

### 3.4 封面

**采集**
- 视频、图文、仓库在采集时取平台封面地址；文章取 RSS 附件或 og:image。
- 封面下载到本地缓存 `data/media/covers/`，转为 WebP，最长边 960px，另存 320px 缩略图。平台图片多有防盗链或带过期签名，所以缓存到本地，而不是在前端直接引用原地址。
- 下载规则：只请求各平台的图片 CDN 域名白名单；限制 5MB；校验 `image/*`；超时 10 秒；失败 3 次后标记失败。
- 计算主色，前端加载时先用主色占位。

**服务与清理**
- `GET /api/v1/media/{asset_id}?size=thumb|full` 返回本地文件，带长期缓存头。
- 缓存上限默认 2GB，超出时按最后访问时间清理；已收藏或被项目引用的封面永久保留。

**展示**
- 横版视频 16:9，竖版（抖音、小红书）9:16 并排展示，显示时长和形态标记。
- 封面缺失或失败时使用生成封面（按标题生成的示波器图形，见样张）。
- 图片懒加载；信息流用缩略图，详情用大图。

### 3.5 评论（条目的附属信息）

评论挂在单个条目下面，是这条内容的补充资料；不进信息流，不单独成页，也不参与排序。

**采集范围**
- 每条内容取热门评论前 20 条，不取回复。
- 评论数照常作为指标写入 `content_metric_observations`。

**触发条件**
1. 你收藏了它。
2. 它被项目用作来源。
3. 在条目详情里点「加载评论」。

收藏和项目来源的评论在采集后 24 小时刷新一次，之后不再刷新。

**`content_comments` 表**（`content_id` 外键，随内容删除）

| 字段 | 说明 |
|---|---|
| `content_id`、`platform`、`platform_comment_id` | 平台内唯一，重复采集时更新点赞数 |
| `author_name` | 只存昵称，不存头像和主页 |
| `text`、`like_count` | 原始数据 |
| `published_at`、`crawled_at` | 时间 |

**评论摘要**：在评论区点「总结评论」时由 AI 生成几条要点，每条附原评论 id；结果存在内容的 `comment_digest`（JSON）字段，标注基于多少条评论。

**保留期**：未收藏内容的评论保留 30 天。

**展示**
- 条目详情底部的「评论」折叠区，默认收起；展开后按点赞排序，顶部可点「总结评论」。
- 创作「选题与创意」的详情里同样以折叠区出现。

### 3.6 字幕与转写

- B站、YouTube 有字幕时自动拉取。
- 其余视频在收藏或用于创作时，点「转写」调用千问语音识别，结果写入 `content_subtitles`。
- AI 分析视频时使用「标题 + 描述 + 字幕」；预筛对视频改用这三者的总长度，不再因描述短而跳过。

### 3.7 调度、后台运行与空档补采

**定时采集**
- 订阅每 2–6 小时，追踪词每天 3–4 次，榜单每 30 分钟，小红书 / 抖音按平台限频单独排队。
- 修正抖音账号被识别为榜单类型的问题。

**后台服务**
- 后端作为后台进程运行，登录 Windows 时自动启动（`start-local.ps1` 注册计划任务）；关闭浏览器界面不影响采集。
- 托盘图标显示状态（运行 / 暂停 / 有异常），菜单：打开工作台、记一笔、暂停采集、退出。托盘程序同时负责 Windows 系统通知（10.1）。

**空档补采**
- 启动时检查每个信源的上次成功时间。订阅和 RSS 按发布时间往回翻页，补到上次成功时间为止，每个信源最多补 7 天 / 200 条。
- 热榜只有当时的快照，空档期间的热榜标记为「缺失」。
- 补回的内容按发布日期归档，缺发布时间的按采集日期；同步记录标记为补采。

### 3.8 采集页（原数据统计）

位置：信源 · 采集。回答「采集在不在正常工作、信源结构对不对」，每块都对应一个动作。

**顶部**
- 一行关键数字，均与 7 天前对比：今日新增、7 天同步成功率、待分析、今日分析花费、漏采数。
- **建议**：系统直接给出结论和动作按钮，例如：
  - 「arXiv cs.AI：30 天 901 条，收藏 0 → 建议停用」
  - 「Wired 连续 3 天 0 条，没有报错 → 可能已失效」
  - 「你收藏的 5 条视频来自同一个 UP 主 → 建议订阅」
  - 「视频类内容 0 条，中文平台 2 个 → 结构偏了」
- **处理记录**：3.9 的自动处理逐条列出，每条可撤销。

**五块内容**

| 块 | 显示 | 动作 |
|---|---|---|
| 健康 | 每个信源一行：状态、上次成功、下次计划、7 天成功率、最近失败原因、每日新增迷你柱；异常排在最前。连续多次 0 条但不报错也算异常 | 重新登录、立即同步、暂停、调整间隔 |
| 覆盖 | 用热榜和追踪词搜索结果对照订阅：48 小时内在你的订阅 / RSS 中找不到同一事件的，列为漏采，例如「Opus 5.5：知乎热榜、B站热门都有，你的订阅 0 条」 | 订阅作者、加追踪词 |
| 完整度 | 各信源的封面、发布时间、作者、平台指标、正文的完整率；发布到采集的延迟中位数 | 换采集方式，或接受缺失 |
| 信源价值 | 30 天内的产出、精选数（分母只算已分析）、被收藏数、用进项目数、与其他信源重复率、最先报道次数、分析花费；收藏趋势（原评分看板）；信源画像（原可信线索） | 降频、停用 |
| 流程 | 漏斗：采到 → 去重 → 预筛（按原因：太短 / 自我推广 / 无正文）→ 快速判断 → 完整分析 → 精选，每段可点开看具体内容 | 处理积压、调整预筛规则 |

另有「结构」小图：按平台、语言、形态看内容占比。

**口径**
- 「平常间隔」取近 30 天相邻两次有新增的中位间隔。
- 「最先报道」：同一事件中发布时间最早的信源记一次。
- 数据来自 `source_sync_runs`、`content_items`、收藏、项目来源、模型用量记录、热榜快照。

### 3.9 自动处理

原则：能撤销、只起保护作用的动作自动执行，事后通知；会改变你长期看到的内容或要花钱的动作，点一下才执行。

| 情况 | 自动动作 |
|---|---|
| 某个信源连续失败 3 次 | 暂停该信源；之后每 6 小时试一次，成功后自动恢复 |
| 登录失效或出现验证码 | 暂停该平台全部浏览器采集；你处理完后恢复 |
| 被平台限流（429 等） | 间隔翻倍；恢复正常后逐步回到原间隔 |
| 不报错，但超过平常间隔 3 倍没有新内容 | 标记「可能失效」并通知，不暂停 |
| 待分析积压 | 按初筛分顺序分析，不超过每日预算（4.2） |

- **点一下执行**：停用或删除信源、因价值低降频、订阅新作者、加追踪词、改预筛规则、超出预算的分析、补采更早的历史。
- **不会自动执行**：删除数据、修改评分权重。
- 处理记录写入 `auto_actions` 表（类型、对象、原因、执行时间、撤销时间），撤销即恢复原状态。

## 4. 分析与评分

### 4.1 分析漏斗

现状是除规则预筛外全部送 AI 分析，按入库先后排队；精选在分析之后才产生。改为先用不花钱的信号挑出值得分析的，再按预算分析。

```text
采到 → 去重 → 规则预筛 → 免费初筛（每条）→ 事件归并（每条）
     → 快速判断（初筛过线的）→ 完整分析（快速判断过线的，受预算约束）
```

| 环节 | 做法 | 成本 | 结果 |
|---|---|---|---|
| 规则预筛 | 现有规则；视频按「标题 + 描述 + 字幕」总长度判断 | 0 | `skip_reason` |
| 免费初筛 | 平台原始指标与增速、上榜排名、同一事件覆盖的平台数、信源历史价值（被收藏 / 精选比例）、命中追踪词、与收藏的相似度、新鲜度，加权合成 | 0 | `triage_score`、`triage_signals` |
| 事件归并 | 本地向量模型（CPU 运行的中文小模型）计算标题 + 摘要向量；时间窗内相似度超过阈值的归为同一事件，写入现有 `content_event_groups` / `content_event_members`。每个事件选一条代表（正文最全、信源价值高、发布最早），只有代表进入后续分析，其他条目继承事件的分析结果 | 0 | 事件与代表条目 |
| 快速判断 | 便宜模型，只看标题和摘要，20 条一批；输出是否值得完整分析、标签、一句中文摘要 | 低 | `analysis_level=quick` |
| 完整分析 | 现有分析流程（评分各维度、角度、风险）。arXiv 只用摘要；长文截取小标题和前若干段；同一内容指纹复用结果 | 高 | `analysis_level=full` |

- **按需补分析**：点开详情、收藏、用作项目来源时，未完整分析的立即分析；不受每日预算限制，计入花费。
- **排序**：未完整分析的条目用初筛分和快速判断结果排序，显示「未分析」。
- 初筛权重和各环节阈值放在「设置 · 评分说明」，可调。

### 4.2 分析预算

- 默认每天 5 元，设置里可改。快速判断和完整分析共用这个预算。
- 按初筛分从高到低分析，到上限即停；剩余的排到次日，排队超过 3 天的不再分析，保留初筛分。
- 采集页显示每天花费和各信源花费；跑一周后按实际花费和效果调整默认值。
- 生成服务（8）和 agent 任务另有各自的预算。

### 4.3 选题结论（原当日精选的评分面板）

条目详情顶部和今日列表都显示结论。原面板一条内容有 20 多个数字，换成结论和依据。

**结论**：值得做 / 观察 / 跳过，加一句理由。结论由规则根据下面的依据计算；理由由依据里的事实拼成，例如「3 个平台在报同一件事；B站相关视频两天播放 120 万；你收藏过 4 条相关内容」。这一步不调用模型。

**依据**

| 依据 | 数据 | 缺失时 |
|---|---|---|
| 热度 | 平台原始指标与增速、上榜排名 | RSS 文章显示「无平台指标」 |
| 时机 | 发布了多久；所属话题的状态（新出现 / 升温 / 持续 / 见顶 / 降温，5.3）；最先出现在哪个平台 | 话题观测不足时显示「观测不足」 |
| 同题 | 同一事件的条数；各平台已有的同题视频 / 图文数（来自追踪词搜索） | 未搜索时显示「未搜索」 |
| 和你相关 | 命中的追踪词；相关收藏数；你对同类内容的「有用 / 不感兴趣」 | — |
| 风险 | 完整分析的风险分 + 规则（来源、敏感词） | 未分析时只显示规则结果 |
| 内容质量（参考） | AI 的信息密度、可操作性等合成一项 | 「未分析」 |

- **缺失项**：单独列出，例如「未采集平台指标」「评论未采集」。
- **角度**：2–3 个可做的角度（完整分析产出），每个都能「用于新项目」；未分析时按钮为「分析并给角度」。
- **计算明细**：公式、权重、系数收进折叠区，默认收起。
- **不对**：你可以改成正确的结论。记录为反馈，参与个性化排序和规则调参；「设置 · 评分说明」显示近 30 天结论与你的标记、收藏、开项目的一致率。
- 列表不再显示 0–100 的排序分，改为结论标记加两三个关键依据（如「3 平台 · 播放 120 万 · 升温」）。

### 4.4 内容保留

- 停止删除 90 天前的待分析内容。原始内容长期保留。
- 只清理封面缓存（3.4）和未收藏内容的评论（3.5）。

## 5. 发现

### 5.1 今日

- 文章、视频、图文、提示词、仓库同在一个流里，可按形态筛选；所有信源一视同仁。
- 头部是「今天的信号」时间线：每个平台一条轨道，条目按发布时间放置，颜色表示形态，亮度表示热度。
- 右侧栏：追踪词（逐小时点阵、各平台条数）、跨平台共振（主题 × 平台矩阵）、采集状态。
- 每条显示结论标记和关键依据（4.3）；指标显示原始值、变化量和观测时间；RSS 文章显示「RSS 无平台指标」。
- 视图：全部（默认）、精选（结论为「值得做」的条目，原当日精选，保留 7 天历史）。
- 每条可标记「有用 / 不感兴趣」。
- 超过 2 天没打开时，顶部显示「你离开了 N 天」，点开进入空档回看（5.4）。

### 5.2 热点（原趋势雷达 + 趋势追踪）

| 标签页 | 内容 | 来自 |
|---|---|---|
| 热榜 | 各平台热搜榜，按分类 / 平台筛选，手动同步，显示排名与原始热度 | 趋势雷达·榜单 |
| 共振 | 同一事件在多个平台同时上榜，可调最低平台数 | 趋势雷达·共振 |
| 升温 | 升温榜：每个话题一行，迷你曲线 + 状态 + 平台分布 + 代表内容 + 结论；可按状态筛选（含「持续」） | 趋势雷达·持续、趋势追踪，按 5.3 重做 |
| 追踪词 | 每个追踪词一条曲线，可按平台拆开；新建 / 编辑 / 预设 | 母题配置 + 新增 |

- 点话题进入专题（5.5）；点条目进入条目详情（5.6）。

### 5.3 趋势计算

| 项 | 做法 |
|---|---|
| 话题单位 | 事件（4.1 归并结果）和追踪词；AI 标签只作辅助，同义词合并（别名表 + 向量相似） |
| 热度信号 | 上榜排名与热度值（热榜快照）、平台指标增量（`content_metric_observations`）、覆盖平台数与信源数；篇数只作辅助显示 |
| 时间 | 发布时间，缺失时用采集时间 |
| 范围 | 全部信源（含你添加的），包括未完整分析的内容（归并和追踪词匹配不依赖 AI 分析）；已归入事件的内容照常计入 |
| 缺数据 | 没有观测的时段显示「观测不足」，不画 0；热榜空档标「缺失」 |
| 状态 | 新出现：首次出现不足 24 小时；升温：近 24 小时信号比前 24 小时增长 ≥50%；持续：连续 3 天以上有信号；见顶：增速转负但仍在高位；降温：比峰值下降 ≥50%。阈值可调 |
| 计算 | 每小时增量计算；扩展现有 `topic_trends`（信号值、状态、平台分布），`calculation_version` 升级；只扫描最近的观测窗口 |

### 5.4 报告

承担长期追踪：一段时间不看，回头仍能看到这段时间发生了什么。

| 类型 | 生成 | 数据范围 |
|---|---|---|
| 日报 | 当天可生成快照；次日 00:30 生成完整版 | 归属日期为当天的内容（发布日期，缺失时用采集日期） |
| 周刊 | 每周一 | 本周 |
| 月刊 | 每月 1 日 | 上月 |
| 任意时间段 | 手动选起止日期 | 所选范围 |
| 空档回看 | 连续 2 天以上没有采集，开机补采完成后自动生成 | 空档期间 |

- **补跑**：启动时检查缺失的日报、周刊、月刊；有采集数据的补生成；没有采集数据的日期不生成日报，在归档日历里标「未采集」。
- **空档期**：每天仍有条目列表，不调用模型；只生成一份空档回看，内容包括这段时间的大事、升温过的话题、追踪词变化、错过的「值得做」内容、你收藏的话题有什么后续；热榜缺失时注明。
- **完整度**：每份报告标注生成时的数据完整度（待分析条数、缺失的信源与热榜）；数据补齐后可重新生成，旧版本保留（沿用现有版本机制）。
- **前后连贯**：每期读取上一期的话题列表，写明「上期提到的 X 有什么后续」「新出现」「降温」。
- **结构**：本期大事、升温 / 降温话题、追踪词变化、持续话题的后续、值得做的选题（带结论）、一行采集概况。
- **归档**：日历视图，每天的格子显示当天头条；全文搜索；按话题筛选；报告中的话题链接到专题。
- **同步**：写入 Obsidian `报告/`；周刊可推送飞书（10.1）。

### 5.5 专题

一个话题从出现到现在的完整经过，可以跨几个月看。

- **来源**：持续 3 天以上的事件自动成为专题；每个追踪词一个专题；任何话题都可以点「关注」。
- **专题页**：
  - 时间线：按发布时间排出所有相关内容，按平台分色。
  - 热度曲线；各平台首次出现的先后。
  - 提到它的报告；相关的收藏、随笔、项目。
  - 当前状态（5.3）和结论（4.3）。
- **归档**：未关注、30 天没有新内容的自动专题归档，仍可搜索。
- **表**：`topic_dossiers`：id、类型（event / watch_term / manual）、标题、关联事件或追踪词、是否关注、状态、首次 / 最近出现时间、归档时间。
- **Obsidian**：专题对应 `主题/` 下的主题页。

### 5.6 条目详情

今日、热点、报告、专题、灵感库共用一个详情（抽屉，可展开为独立页 `/items/[id]`）：

- 顶部：结论与依据（4.3）。
- 原文 / 视频预览（原阅读器）、封面、作者、发布与采集时间。
- 指标与观测曲线。
- 同一事件的其他来源、所属专题；归错时点「移出此事件」。
- 角度；收藏、记入随笔、用于新项目、记入飞书（10.2）。
- 评论折叠区（3.5）。
- 经历：这条内容从采集到成片的过程（2.3）。

## 6. 灵感库

### 6.1 条目类型

| 类型 | 内容 |
|---|---|
| 文章、视频、图文 | 来自采集或粘贴链接，含封面、作者、指标；评论在详情的折叠区 |
| 提示词 | 正文、变量、适用模型、示例输出（可关联生成图）、出处 |
| 代码仓库 | README 摘要、Star 数、语言、最近发布 |
| 美术素材 | 图片（照片、插画、海报、截图）、配色、字体、图标与贴纸、纹理、动图与视频片段、音乐与音效 |
| 生成图 | 工作台或外部工具生成的图，带提示词、模型、参数、参考图 |
| 随笔 | 见 6.4 |
| 链接 | 任意网页 |
| 风格、模板 | 可以在项目里直接套用（6.6） |

- 从视频描述或网页中提取提示词和仓库链接，作为独立条目，同时关联到原内容。

### 6.2 收进来

| 方式 | 说明 |
|---|---|
| 一键收藏 | 今日、热点、专题、条目详情 |
| 粘贴链接 | 自动识别 B站、抖音、小红书、YouTube、GitHub、任意网页，拉取标题、封面、作者、指标 |
| 浏览器扩展（Edge） | 任意网页右键「存到灵感库」：图片、链接、选中文字；可拖图片到扩展面板。扩展只调用本机工作台接口 |
| 剪贴板 | 在灵感库页或随笔输入框粘贴截图、图片、链接 |
| 本地文件 | 拖入文件或文件夹批量导入 |
| 素材收件箱 | 设置里指定一个文件夹，放进去的文件自动导入，导入后移到其中的 `已导入/` |
| 从内容取图 | 文章配图；视频截帧（指定时间点） |
| 生成 | 工作台生图（7.4、8） |
| 外部生成图 | 导入时读取 PNG 元数据里的提示词和参数（SD WebUI 的 `parameters`、ComfyUI 的 `prompt` / `workflow`） |

收藏时不选类别，收进来的都是素材；需要时再提炼成风格或模板（6.6）。

### 6.3 素材存储与授权

**存储**
- 原文件存 `data/library/`，按 sha256 去重，文件名为哈希；数据库只记路径。
- 图片生成 320px / 960px WebP 缩略图；视频片段生成封面帧和时长；音频生成波形和时长。
- 记录：类型、尺寸、时长、主色（配色素材存色值列表）、来源地址、导入方式。
- 字体读取字体名和字重，生成字样预览，可被视觉风格引用。
- 灵感库素材不自动清理；设置里显示占用空间。

**授权状态**

| 状态 | 默认用于 |
|---|---|
| 自有 | 手动标记 |
| 可商用 | 手动标记 |
| 仅参考 | 手动标记 |
| 未知 | 网络收藏、本地导入的默认值；可批量修改 |
| AI 生成 | 生成图，附模型名；能否商用以模型条款为准 |

- 放进成片时，「仅参考」「未知」的素材会提醒，不阻止。
- 提示词包的素材清单列出授权状态。

### 6.4 随笔

- **随手记**：任何页面按 `Alt+N` 或点右下角按钮，弹出输入框，写一句就存，不打断当前操作；托盘菜单也能「记一笔」。
- **内容**：文字（Markdown）、图片、语音（录音后用千问转写成文字，保留音频）、链接（自动收进灵感库并关联）。
- **关联**：用 `[[ ]]` 关联收藏、专题、项目和其他随笔；`#标签`。
- **随笔页**：按日期排成时间线，像日记；可按标签、关联对象筛选。
- **相关提示**：保存后显示相关的收藏和热点（本地向量比对）。
- **开项目**：选一条或多条随笔「用于新项目」，作为项目的参考来源。
- **Obsidian**：每天一个文件 `随笔/2026-10-18.md`，每条随笔一个带时间的小节（`## 14:32 ^cw-123`）；在 Obsidian 里新增的小节读回为新随笔。

### 6.5 组织与搜索

- **标签**：AI 自动打 + 手动。
- **画板**：像花瓣那样把任意类型的条目放进同一个画板，按主题或项目组织。
- **搜索**：
  - 全文：PostgreSQL `pg_trgm` + 中文分词。
  - 图片：文字搜图（AI 描述 + 图片向量）、以图搜图、按颜色。
  - 筛选：形态、平台、授权、时间。
- **AI 描述**：图片向量用本地模型计算，不花钱；文字描述和标签（主体、风格、构图、色调）用视觉模型，计入每日预算，可在设置里关闭。
- **视图**：图谱、列表、瀑布流画廊（素材默认瀑布流）。
- 默认按最近收藏排序；内置的风格和模板不进库。

### 6.6 风格与模板

**区分**：素材只能参考；风格和模板写成了规则，能在项目里直接选用、AI 能照着执行。风格是色板、字体、版式、动效；模板是结构、语气。

**进入方式**
- 新建；复制内置。
- 从素材「提炼为风格 / 模板」：AI 读取选中的素材写出规则，素材作为参考保持关联，图谱里显示这条关联。
- 在项目的风格选择器里输入名称点「AI 生成」：AI 读取带同名标签的收藏作参考（可勾选）。
- 从项目「存为模板」。

例：平时收藏包豪斯海报并打标签。项目里在风格选择器输入「包豪斯」，库里没有就点「AI 生成」，AI 参考这些海报写出规则（红黄蓝加黑白、几何无衬线字体、网格版式、硬切和几何位移动效），存为风格并关联海报。若是要介绍包豪斯这个主题，那些收藏就是项目来源；两者可以同时用。

**展示**：内置风格 / 模板只出现在项目的选择器里；灵感库按「风格 / 模板」筛选时只列你自己的。

**数据**
- 表：`content_templates` / `content_template_versions`、`visual_styles` / `visual_style_versions`。
- 内容模板版本：用途、受众、结构（段落与要点）、语气、参考片段（可关联采集内容）、适用形态、推荐风格、封面。
- 视觉风格版本：色板、字体（可引用灵感库字体）、版式与构图规则、动效规则、参考图（引用灵感库素材）、适用形态。
- 版本一经创建不可修改；编辑即生成新版本；工程固定引用版本，有新版本时提示手动升级。
- 内置模板改为种子数据，按 key 幂等写入；编辑内置模板时复制成自定义模板。
- 接口：`/api/v1/templates`、`/api/v1/styles`（列表、新建、详情、新增版本、版本历史、归档、复制、提炼）；`/studio/catalog` 返回形状不变。
- 「设置 · Prompt」是工作台自己分析内容用的系统 Prompt，与灵感库里收藏的提示词无关。

### 6.7 关联与图谱

- **关联来源**：同一事件 / 专题、同标签、同作者、语义相似（取最相近的 5 条）、被项目使用、提炼关系（素材 → 风格 / 模板）、生成关系（提示词 / 参考图 → 生成图）、你写的 `[[双链]]` 和手动关联。
- **图谱**：sigma.js + graphology（WebGL）。颜色表示类型，大小表示关联数；可筛选类型和时间；从节点可直接「用于新项目」。详情里显示局部图谱（一度、二度关系）。

### 6.8 Obsidian 双向同步（演示重点）

- 设置里填写 vault 路径，工作台写入 `创意工作台/` 目录：`收藏/`、`素材/`、`提示词/`、`仓库/`、`随笔/`、`项目/`、`主题/`、`报告/`。
- 每条笔记：
  - frontmatter：`cw_id`、类型、平台、链接、作者、发布 / 收藏时间、标签、授权、最新指标、工作台链接。
  - `## 摘要`：工作台维护。
  - `## 我的笔记`：归你写，工作台只读取。
  - `## 关联`：自动生成的 `[[双链]]`。
- 素材笔记嵌入缩略图（vault 内 `_附件/` 下的缩略图），原文件留在工作台。
- 每个专题生成主题页，链接到所有相关条目、随笔和报告。
- 工作台监听目录变化：读回标签、双链、「我的笔记」和新增的随笔小节；新建的笔记作为「随笔」进入灵感库。
- 字段归属：结构化字段归工作台，「我的笔记」、随笔正文和手写双链归你；两边各改各的部分，不会互相覆盖。
- 跳转：工作台「在 Obsidian 打开」（`obsidian://open`）；笔记里的工作台链接可点回。

### 6.9 旧收藏夹迁移

| 类型 | 去向 |
|---|---|
| content、video、audio、image | 灵感库（文章 / 视频 / 音乐 / 图片），已上传的文件迁入 `data/library/` |
| trend、topic_group | 专题（关注） |
| book | 灵感库（链接）；网文模块已移除 |
| template、style | 风格与模板表（迁移为 v1）；旧工程的 `favorite:template:{id}` 映射到新 key |
| author、creator、source、feed | 信源（订阅） |
| project | 项目（星标） |
| work | 作品（星标）；成片不再自动写入收藏 |

## 7. 创作工作台

一个项目对应一个选题，项目里有多个产出物。页面线框、交互、组件、数据模型、接口与测试见 `创作工作台设计与实现.md`；本节为概要。

各步骤里的 AI 操作（给出方向、写初稿、修改、制作、平台改写）都以流程运行（2.2），过程在项目的「过程」页签查看（2.3）。

### 7.1 选题与创意

- 左：选题列表，来源可切换（灵感库 / 今日 / 热点 / 专题 / 手动输入），可搜索，可按形态筛选。
- 右：详情，含结论、封面、摘要、指标、原文 / 视频预览、同题内容；评论在底部折叠区。
- 情绪板：从灵感库拖入图片、风格、提示词、随笔，作为创意参考。
- AI 给出 3–5 个创意方向（文章角度、故事讲解、MV 主题），读取来源和情绪板；也可以自己写。
- 确定主题、创作方向、目标产出后进入文稿。

### 7.2 文稿

- 三栏：左大纲（段落 / 分镜目录），中编辑器（纸面），右面板（AI 助手 / 设定 / 版本 / 来源）。
- AI 助手的修改以建议形式出现，逐段接受或拒绝。
- 版本对比按需打开，并排显示。
- 视频形态切换为脚本视图：旁白 + 分镜表（时长、画面、旁白、字幕），每行可单独改写。
- 状态：草稿 → 已定稿。定稿锁定文案层（选题、内容形态、内容模板、受众、创作思路、时长、成稿）。

### 7.3 产出

| 产出物 | 做法 |
|---|---|
| 小红书版 | 标题 ≤20 字、正文、话题、封面文案、配图（可生图）；复制 / 导出，打开发布页 |
| 知乎版 | 文章 / 回答 Markdown；复制 / 导出 |
| 公众号版 | 排版 HTML、摘要、封面（可生图）；复制到编辑器；草稿箱接口为后续可选项 |
| 一键成片 | 讲解视频流程：分镜 → 美术 → 制作（DeepSeek Harness / Claude Code / Codex + Remotion + 千问配音）→ 质检（2.2）；可使用项目素材 |
| 视频提示词包 | 定稿脚本、分镜、风格规范、素材清单（含授权）、交付要求；复制 / 下载，或由外部 agent 通过工作台工具直接读取并把成片交回 |
| 音乐 MV | 你提供歌曲和 LRC，同样支持一键成片和提示词包 |

- 制作层参数（视觉风格、表现方案、制作方式、画幅、字幕卡）在产出页设置，修改后定稿保持不变。
- 制作时读取「定稿版本的文案 + 当前制作参数」，并把本次参数写入作品记录（`studio_artifacts.settings`，增量迁移）。
- 平台版本由定稿改写而来，各自独立编辑，不回写定稿。
- 项目素材（图片、分镜关键帧、配乐）可放进成片；授权为「仅参考」「未知」的会提醒。

### 7.4 用灵感生图

- **入口**：情绪板、文稿插图位置、小红书配图、公众号封面、分镜关键帧、MV 画面。
- **参考**：从灵感库选图片、风格、提示词。风格的规则转写进提示词；参考图在模型支持时作为图生图输入。
- **提示词**：AI 根据文稿段落或分镜加风格生成，可修改。
- **结果**：一次出多张候选。选中的进入项目素材，同时作为「生成图」存入灵感库，记录提示词、模型、参数和参考条目。可以「出变体」或「以此为参考再生成」。
- 分镜关键帧可用作一键成片的画面素材，或视频生成的首帧（8）。

## 8. 生成服务接入

- **通用接口**：
  - `generate_image(prompt, refs, size, n, params) → images`
  - `generate_video(prompt, first_frame, duration, aspect) → 任务`
  - `generate_music(...)`：预留
- **设置 · 生成服务**：每个服务填名称、类型（图片 / 视频 / 音乐）、接口格式、地址、Key（本地加密保存）、模型、支持的能力（文生图、参考图、尺寸、张数、视频时长 / 画幅）、单价（用于花费统计）。
- **接口格式**：先实现 OpenAI 兼容的图像接口（image2.5 等模型走这一种）；按需增加厂商适配器（通义万相、可灵、即梦、Veo 等）。
- **异步任务**：视频生成进任务中心，轮询厂商任务状态，结果下载到本地。
- **记录**：`generation_jobs` 表：类型、服务、模型、提示词、参考条目、参数、结果文件、花费、状态、所属项目 / 产出物。
- **预算**：生成服务单独设每日上限，超出时提示。
- 讲解视频仍以 Remotion 动画为主；视频生成用于分镜画面和短片段。

## 9. 任务中心与作品库

- 任务中心：制作、生成、分析、同步（原「采集任务」页）都在这里。显示状态、类型、所属项目、耗时、花费；失败原因写清楚怎么处理，一键重试；日志默认折叠，只显示阶段进度条；流程运行可打开节点图、时间线、调用树（2.3）。

## 15. 风险与约束

- **平台规则**：抖音、小红书采集可能违反平台用户协议，采集账号有被限制的风险；仅采集公开内容，低频，用于个人研究。
- **评论隐私**：只存昵称与文本，不存头像和主页；未收藏内容的评论 30 天后删除。
- **素材版权**：网络收藏的素材默认「未知」；放进成片时提醒；授权状态写进提示词包。
- **成本**：分析、评论摘要、字幕转写、图片描述、生成服务、agent 任务都会花钱；各有每日上限，采集页和任务中心显示花费。
- **平台变化**：平台接口和页面结构会变；适配器出错时只影响该平台，采集页显示失败原因。
- **本地资源**：后台服务常驻；采集并发受限。素材原文件不自动清理，设置里显示占用空间。
- **Agent 循环与成本**：评审和质检循环有上限，每次运行有预算，超限暂停。
- **外部 agent**：只在独立工作目录运行，只拿到所需密钥；工作台数据只能通过 MCP 工具访问，每次调用都有记录。
- **追溯数据增长**：载荷压缩存文件；设置里显示占用，可手动清理。
- **框架依赖**：LangGraph 锁定版本；编排之外的模块不依赖它。
- **运行环境**：本地 Windows；浏览器采集依赖本机 Edge。
